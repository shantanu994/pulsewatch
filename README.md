# PulseWatch

PulseWatch is a FastAPI-based service for tracking website uptime and managing user-owned monitoring targets. It includes JWT authentication, monitor registration, and a simple Celery-based health-check flow for background URL validation.

## Features

- User signup and login with JWT-based authentication
- Protected endpoints for creating and listing monitors
- Async SQLAlchemy access with PostgreSQL
- Alembic migrations for schema management
- Redis + Celery support for background URL checks
- Docker Compose setup for local PostgreSQL and Redis services

## Tech Stack

- Python 3.11+
- FastAPI
- SQLAlchemy + async PostgreSQL
- Alembic
- Celery
- Redis
- Pydantic
- Passlib / bcrypt
- python-jose

## Project Structure

- `main.py` — FastAPI app and route definitions
- `app/database.py` — database engine and session factory
- `app/models.py` — SQLAlchemy models for users and monitors
- `app/schemas.py` — Pydantic request and response models
- `app/security.py` — password hashing and JWT helpers
- `app/tasks.py` — Celery task logic for URL checks
- `app/celery_app.py` — Celery configuration
- `alembic/` — migration files and metadata
- `docker-compose.yml` — local PostgreSQL and Redis services
- `requirements.txt` — Python dependencies
- `test_task.py` — basic task verification script

## Requirements

Before starting the project, make sure you have:

- Python 3.11 or newer
- Docker and Docker Compose
- A PostgreSQL database available locally or through Docker
- Redis running locally or through Docker

## Local Development Setup

### 1) Clone the repository

```bash
git clone <repo-url>
cd pulsewatch
```

### 2) Create and activate a virtual environment

Windows (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

macOS/Linux:

```bash
python -m venv .venv
source .venv/bin/activate
```

### 3) Install dependencies

```bash
pip install -r requirements.txt
```

### 4) Configure environment variables

Create a `.env` file in the project root with the following values:

```env
DATABASE_URL=postgresql+asyncpg://pulsewatch:pulsewatch123@localhost:5432/pulsewatch
SECRET_KEY=replace-with-a-long-random-secret
REDIS_URL=redis://localhost:6379/0
```

Notes:

- `DATABASE_URL` should match the PostgreSQL instance you want to use.
- `SECRET_KEY` is used for JWT generation and validation.
- `REDIS_URL` is used by Celery and the background worker.

### 5) Start PostgreSQL and Redis

The project includes Docker Compose support for local infrastructure:

```bash
docker compose up -d postgres redis
```

This starts:

- PostgreSQL on `localhost:5432`
- Redis on `localhost:6379`

### 6) Run database migrations

```bash
alembic upgrade head
```

If the database is empty and the migration files are present, this creates the schema.

### 7) Start the API server

```bash
uvicorn main:app --reload
```

The application will be available at:

- `http://127.0.0.1:8000`

You can also view the autogenerated docs at:

- `http://127.0.0.1:8000/docs`
- `http://127.0.0.1:8000/redoc`

## API Endpoints

### Authentication

- `POST /auth/signup` — create a new user
- `POST /auth/login` — authenticate a user and receive a JWT
- `GET /auth/me` — return the currently authenticated user

### Monitors

- `POST /monitors` — create a new monitor for the current user
- `GET /monitors` — list monitors belonging to the current user

### Health check

- `GET /` — simple service status response

## Example Flow

1. Sign up with a valid email and password.
2. Log in to receive a bearer token.
3. Send the token in the `Authorization` header on protected routes:

```http
Authorization: Bearer <token>
```

4. Create monitors by posting a URL and a polling interval.

## Example Requests

### Sign up

```bash
curl -X POST "http://127.0.0.1:8000/auth/signup" \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"secret123"}'
```

### Log in

```bash
curl -X POST "http://127.0.0.1:8000/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"secret123"}'
```

### Create a monitor

```bash
curl -X POST "http://127.0.0.1:8000/monitors" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com","interval_seconds":300}'
```

## Celery Tasks

The project includes a basic Celery task in `app/tasks.py`:

```python
@celery_app.task
def check_url(url: str):
    ...
```

Run the worker with:

```bash
celery -A app.celery_app worker --loglevel=info
```

This is useful for background URL checks and future monitor scheduling logic.

## Database and Migration Notes

- Models live in `app/models.py`.
- Alembic migrations are stored in `alembic/versions/`.
- When changing models, generate and apply a migration:

```bash
alembic revision --autogenerate -m "describe change"
alembic upgrade head
```

## Troubleshooting

- If the app cannot connect to PostgreSQL, verify the `DATABASE_URL` value and confirm the database container is running.
- If JWT auth fails, make sure `SECRET_KEY` is set and non-empty.
- If Celery cannot connect, confirm Redis is running on `localhost:6379`.
- If `alembic upgrade head` fails, check that the database credentials and connection settings are correct.
